# AskAnything Analytics Agent

An agentic analytics layer on top of the fine-tuned **Qwen2.5-VL-7B ChartQA LoRA** in this repo.
Ask a business question in plain language and get back an answer **plus the evidence behind it**:
the governed SQL that produced the number, a chart, a check that the chart matches the data, and a full audit trace.

> All data here is **synthetic** (generated by `agentic/data/generate_synthetic.py`), shaped like an
> iron-ore value chain: ore hoisted, pellets produced, energy, CO2, equipment downtime.

## Why this exists

Most "chat with your data" demos let an LLM write free-form SQL, so two users can get two different
numbers for the same KPI. This project takes the opposite approach:

| Principle | How it is implemented |
|---|---|
| **One definition per metric** | `agentic/semantic/metrics.yml` is the semantic model. The agent only chooses *metric + dimensions + period*; SQL is compiled from the model. The same file exports **Power BI DAX measures** (`GET /metrics/dax`). |
| **Answers come with evidence** | Every response includes SQL, bound parameters, rows, charts, verification report and a JSONL trace. |
| **Charts are verified** | The fine-tuned ChartQA model reads the rendered chart back; values must match the SQL result within 5%. |
| **Dashboards can be reconciled** | Upload a screenshot of an existing dashboard or report figure; the agent reads it with the ChartQA model and flags it if it disagrees with the governed numbers. |
| **Secure by default** | Read-only DuckDB connection, sqlglot guard (single SELECT, allow-listed tables, no file/network functions), parameter binding, row caps, no arbitrary file paths for tools. |
| **Tested and gated in CI** | 22 pytest tests, ruff, golden-question evaluation with an accuracy threshold, on every push. |

## Architecture

```
question (+ optional chart image)
        │
        ▼
 ┌──────────────┐   JSON action   ┌───────────────────────────────────────────────┐
 │   Planner    │ ──────────────▶ │ Tools                                          │
 │ LLM (any     │                 │  list_metrics   semantic model catalog         │
 │ OpenAI-compat│ ◀────────────── │  query_metric   spec → compiled SQL → DuckDB   │
 │ endpoint) or │   observation   │  run_sql        guarded, flagged "ungoverned"  │
 │ rule baseline│                 │  make_chart     matplotlib, values labelled    │
 └──────────────┘                 │  read_chart     Qwen2.5-VL-7B + ChartQA LoRA   │
        │                         │  verify_chart   chart ↔ data consistency       │
        ▼                         └───────────────────────────────────────────────┘
 answer + evidence pack + trace.jsonl  (outputs/agent_runs/<run_id>/)
```

| Path | Role |
|---|---|
| `agentic/semantic/metrics.yml`, `layer.py` | Semantic model, spec validation, SQL + DAX compilation |
| `agentic/tools/warehouse.py` | Read-only warehouse access + SQL guard |
| `agentic/tools/charting.py` | Chart rendering designed to be machine-readable |
| `agentic/tools/chart_reader.py` | ChartQA VLM wrapper (`qwen`) and CI stand-in (`mock`) |
| `agentic/agent/planners.py` | LLM planner (JSON tool protocol) and rule-based baseline |
| `agentic/agent/orchestrator.py` | Agent loop, tool dispatch, evidence pack |
| `agentic/agent/verifier.py` | Self-verification and dashboard reconciliation |
| `agentic/api.py`, `agentic/cli.py` | FastAPI service and CLI |
| `evaluations/eval_agent.py` | Golden-set evaluation (routing, answer accuracy, verification rate) |

## Quick start (CPU, no GPU needed)

```bash
pip install -r requirements-agentic.txt
python -m agentic.data.generate_synthetic
python -m agentic.cli ask "Which site had the highest energy intensity last quarter?"
python -m agentic.cli ask "Monthly pellet production by site in 2025" --json
uvicorn agentic.api:app --port 8000        # then open http://localhost:8000/docs
```

## Full mode

```bash
# 1) Real chart reader: the fine-tuned model from this repo (GPU with 16GB+ VRAM)
pip install torch transformers peft accelerate qwen-vl-utils pillow
export VLM_BACKEND=qwen

# 2) LLM planner: any OpenAI-compatible endpoint, e.g. a local Ollama model
export LLM_BASE_URL=http://localhost:11434/v1
export LLM_MODEL=qwen2.5:7b-instruct

python evaluations/eval_agent.py          # compare against the rule-based baseline
```

## Evaluation

`evaluations/golden_questions.jsonl` holds questions with **independently written ground-truth SQL**.
The harness reports routing accuracy (right metric and dimensions), answer accuracy and chart verification pass rate,
and CI fails below `--min-accuracy 0.9`.

Current numbers: the rule-based planner with the mock reader scores 10/10. That is a **baseline and a regression gate,
not a quality claim**: the rules were written alongside these questions. The meaningful results come from running the
same set with `LLM_BASE_URL` and `VLM_BACKEND=qwen`: record those numbers here.

| Configuration | Routing | Answer accuracy | Verification pass |
|---|---|---|---|
| Rule planner + mock reader (CI) | 1.00 | 1.00 | 1.00 |
| LLM planner + Qwen ChartQA LoRA | _run and fill in_ | | |

## Limitations and next steps

- Synthetic data only; the warehouse adapter is DuckDB. Swapping to a cloud warehouse (Fabric, Databricks, Snowflake)
  only touches `Warehouse.execute` and the SQL dialect.
- The semantic model is a small YAML; in production it would be generated from, or kept in sync with, dbt / Power BI models.
- Verification checks the maximum value and top label; extending it to every labelled point is straightforward.
- No authentication in the API yet: put it behind the organisation's identity provider before exposing it.
