# AskAnything in Charts: Fine-tuned Qwen2.5-VL + Agentic Analytics

This repository has two layers:

1. **A chart-understanding model.** Qwen2.5-VL-7B fine-tuned with LoRA on ChartQA, improving exact-match accuracy from **57.5% to 66.0%**.
2. **An agentic analytics layer** (`agentic/`) built on that model. You ask a business question in plain language and get a governed answer, a chart, and a check that the chart matches the data. It can also read an existing dashboard screenshot and flag numbers that disagree with the warehouse.

## 🤖 Agentic Analytics Layer

### How it is used

| Use | Example |
|---|---|
| **Ask** | "Which site had the highest energy intensity last quarter?" returns the answer, a chart, and the SQL behind it. |
| **Reconcile** | Upload a dashboard screenshot. The ChartQA model reads it, and the agent flags numbers that differ from the warehouse. |
| **Reuse** | One metric definition serves the agent (compiled to SQL), Power BI (exported as DAX), and other systems (through the API). |

### How it works

```
question (+ optional chart image)
        │
        ▼
 ┌──────────────┐   JSON action   ┌───────────────────────────────────────────────┐
 │   Planner    │ ──────────────▶ │ Tools                                          │
 │ LLM (any     │                 │  list_metrics   semantic model catalog         │
 │ OpenAI-compat│ ◀────────────── │  query_metric   spec → compiled SQL → DuckDB   │
 │ endpoint) or │   observation   │  run_sql        guarded, flagged "ungoverned"  │
 │ rule baseline│                 │  make_chart     values printed on the chart    │
 └──────────────┘                 │  read_chart     Qwen2.5-VL-7B + ChartQA LoRA   │
        │                         │  verify_chart   chart ↔ data within 5%         │
        ▼                         └───────────────────────────────────────────────┘
 answer + evidence pack + trace.jsonl  (outputs/agent_runs/<run_id>/)
```

The design principles:

- **One definition per metric.** `agentic/semantic/metrics.yml` is the semantic model. The agent only chooses a metric, dimensions and a period; the SQL is compiled from the model, never written freely by the LLM. The same file exports Power BI DAX measures.
- **Answers come with evidence.** Every response includes the SQL, bound parameters, rows, charts, the verification report and a JSONL audit trace.
- **Charts are verified.** The fine-tuned ChartQA model reads the rendered chart back. The highest value must match the SQL result within 5% and the top label must match. An unreadable chart is reported as *inconclusive*, never as a match.
- **Secure by default.** The DuckDB connection is read-only, and a sqlglot guard allows only a single SELECT on allow-listed tables with no file or network functions. Filter values are bound as parameters, rows are capped, and tools cannot open arbitrary file paths.
- **Tested and gated in CI.** GitHub Actions runs ruff, 22 pytest tests and a golden-question evaluation with an accuracy threshold on every push.

### Quick start (CPU, no GPU needed)

```bash
pip install -r requirements-agentic.txt
python -m agentic.data.generate_synthetic          # synthetic mining warehouse (DuckDB)
python -m agentic.cli ask "Which site had the highest energy intensity last quarter?"
python -m agentic.cli ask "Monthly pellet production by site in 2025" --json
python -m agentic.cli export-dax                   # metrics as Power BI DAX measures
uvicorn agentic.api:app --port 8000                # API docs at http://localhost:8000/docs
```

Example output:

```
Södra has the highest energy intensity in Q2 2026: 126 kWh/t. Ranking (kWh/t): Södra 126, Norra 118, Väst 109.
Chart read-back check passed (mock reader; set VLM_BACKEND=qwen for the real model).
```

> All agent data is **synthetic**, generated by `agentic/data/generate_synthetic.py` and shaped like an iron-ore value chain (ore hoisted, pellets produced, energy, CO2, equipment downtime). No real company data is used.

### Full mode (real model + LLM planner)

```bash
# Chart reader: the fine-tuned model from this repo (GPU with 16GB+ VRAM)
pip install torch transformers peft accelerate qwen-vl-utils pillow
export VLM_BACKEND=qwen

# Planner: any OpenAI-compatible endpoint, e.g. a local Ollama model
export LLM_BASE_URL=http://localhost:11434/v1
export LLM_MODEL=qwen2.5:7b-instruct

python evaluations/eval_agent.py
```

### API

| Endpoint | Purpose |
|---|---|
| `GET /health` | Planner, chart reader and data freshness |
| `GET /metrics` | Governed metric catalog |
| `GET /metrics/dax` | The same metrics as Power BI DAX measures |
| `POST /ask` | `{"question": "..."}` → answer + evidence pack |
| `POST /ask-with-chart` | Question + PNG/JPEG upload → read and reconcile a chart |
| `GET /runs/{run_id}/{file}` | Charts and traces of a run |

### Agent evaluation

`evaluations/golden_questions.jsonl` contains questions with **independently written ground-truth SQL**. The harness reports:
- **routing accuracy:** whether the agent picked the right metric and dimensions;
- **answer accuracy:** whether its top result matches the ground truth;
- **verification pass rate:** how often the chart check passed.

| Configuration | Routing | Answer accuracy | Verification pass |
|---|---|---|---|
| Rule planner + mock reader (CI) | 1.00 | 1.00 | 1.00 |
| LLM planner + Qwen ChartQA LoRA | _to be measured_ | | |

The CI result is a **regression gate, not a quality claim**: the rule-based planner was written alongside these questions. The LLM + real-model row is the meaningful measurement.

More detail: [AGENTIC.md](AGENTIC.md).

## 🎯 Model Performance

| Model | ChartQA Accuracy | Improvement |
|---|---|---|
| Qwen2.5-VL-7B | **57.5%** | - |
| **Qwen2.5-VL-7B + LoRA SFT** | **66.0%** | **+8.5 points** |

Evaluated on 500 examples from the ChartQA validation set using exact match, with normalization and numeric tolerance. Verbose-but-correct answers were excluded when selecting "improved" examples.

### What improved

| Category | Description |
|---|---|
| ✅ **Concise answers** | Returns exact values without verbose explanations |
| ✅ **Label recognition** | Better at reading text labels from charts |
| ✅ **Color identification** | More accurate at identifying chart colors |
| ✅ **Statistical calculations** | Improved at medians, ratios, differences |
| ✅ **Counting** | Better accuracy in counting chart elements |
| ✅ **Region comparison** | Accurate comparisons across chart regions |
| ✅ **Yes/No questions** | More reliable binary responses |

### Option 3: Use the model in Python

```python
import torch
from peft import PeftModel
from qwen_vl_utils import process_vision_info
from transformers import AutoProcessor, Qwen2_5_VLForConditionalGeneration

base = Qwen2_5_VLForConditionalGeneration.from_pretrained(
    "Qwen/Qwen2.5-VL-7B-Instruct", torch_dtype=torch.bfloat16, device_map="auto")
model = PeftModel.from_pretrained(base, "prakashchhipa/Qwen2.5-VL-7B-ChartQA-LoRA").merge_and_unload()
processor = AutoProcessor.from_pretrained("prakashchhipa/Qwen2.5-VL-7B-ChartQA-LoRA")

messages = [{"role": "user", "content": [
    {"type": "image", "image": "file:///path/to/chart.png"},
    {"type": "text", "text": "What is the highest value in the chart?"},
]}]
text = processor.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
images, videos = process_vision_info(messages)
inputs = processor(text=[text], images=images, videos=videos, padding=True, return_tensors="pt").to(model.device)
out = model.generate(**inputs, max_new_tokens=48, do_sample=False)
print(processor.batch_decode(out[:, inputs.input_ids.shape[1]:], skip_special_tokens=True)[0])
```

The same logic is wrapped in `agentic/tools/chart_reader.py` (`QwenChartReader`).

## 📊 Data Setup (model training)

The ChartQA dataset is **not** included. Download it from the [ChartQA repository](https://github.com/vis-nlp/ChartQA) and place it as:

```
data/
├── chartqa_train.json      # ~50K training examples
└── images/
    ├── train/  0000.png, 0001.png, ...
    └── val/    0000.png, ...
```

The training script builds a preprocessing cache in `cache/sft_chartqa_textvqa/` (about 2–5 GB, not in git) on the first run. Delete `cache/` to start fresh.

For multi-GPU training:

```bash
export CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7
export NCCL_DEBUG=WARN NCCL_NVLS_ENABLE=0 NCCL_IB_DISABLE=1 NCCL_P2P_DISABLE=1
```

## 🛠️ Technical Details

| | |
|---|---|
| **Base model** | [Qwen/Qwen2.5-VL-7B-Instruct](https://huggingface.co/Qwen/Qwen2.5-VL-7B-Instruct) |
| **Method** | LoRA on vision and language attention layers, rank 64, alpha 16 |
| **Training** | ChartQA, 6 epochs, learning rate 4e-5, ~50–200 samples per epoch |
| **Framework** | HuggingFace Transformers + PEFT + DeepSpeed |
| **Hardware** | Inference: 16GB+ VRAM · Training: 24GB+ VRAM recommended |
